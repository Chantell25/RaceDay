# RaceDay API Endpoint Plan

**Module:** PROG6212 Programming 2B  
**Part:** Part 1 – System Planning and Database  
**System:** RaceDay – South African Road Event Management Platform

## API conventions

- Base route: `/api`
- Authentication: JWT Bearer token.
- `Public` endpoints require no login.
- `Participant` endpoints require a valid participant JWT.
- `Organiser` endpoints require a valid organiser JWT.
- All authenticated endpoints also reject inactive accounts.
- JSON is used for request and response bodies.
- IDs are integer identifiers generated by SQL Server.
- Successful create operations return `201 Created`; successful reads/updates return `200 OK`; deletes return `204 No Content`.
- Validation failures return `400 Bad Request`.
- Authentication failures return `401 Unauthorized`.
- Authenticated users without the required role return `403 Forbidden`.
- Missing resources return `404 Not Found`.
- Duplicate email/enrolment/category constraints return `409 Conflict` where applicable.

## Endpoint table

| HTTP Method | Route | Description | Role Required | Request Body | Expected Response |
|---|---|---|---|---|---|
| POST | `/api/auth/register` | Creates a participant account. | Public | `firstName, lastName, email, password, dateOfBirth, emergencyContactName, emergencyContactNumber` | `201` with `userId, role, email`; `400` validation error; `409` duplicate email |
| POST | `/api/auth/login` | Authenticates a user and issues a JWT. | Public | `email, password` | `200` with `token, expiresAt, userId, role`; `401` invalid credentials |
| GET | `/api/profile` | Returns the logged-in user's profile. | Participant / Organiser | None | `200` profile; `401` unauthenticated |
| PUT | `/api/profile` | Updates the logged-in user's profile. | Participant / Organiser | Editable profile fields | `200` updated profile; `400` validation error |
| GET | `/api/events` | Browses events, optionally filtered by city, date, status, or category. | Public | None; query parameters | `200` event list |
| GET | `/api/events/{id}` | Returns one event with its categories and summary information. | Public | None | `200` event details; `404` event not found |
| POST | `/api/events` | Creates a new event owned by the logged-in organiser. | Organiser | `eventName, description, eventDate, venue, city, status` | `201` event; `400` validation error; `403` wrong role |
| PUT | `/api/events/{id}` | Updates an event owned by the logged-in organiser. | Organiser | Editable event fields | `200` updated event; `403` not owner; `404` not found |
| DELETE | `/api/events/{id}` | Deletes an event owned by the logged-in organiser when it has no completed enrolment dependencies. | Organiser | None | `204`; `409` if deletion is blocked; `403` not owner |
| GET | `/api/events/{id}/categories` | Lists categories belonging to an event. | Public | None | `200` category list; `404` event not found |
| POST | `/api/events/{id}/categories` | Adds a category to an organiser-owned event. | Organiser | `categoryName, distanceKm, maxParticipants, entryFee` | `201` category; `400` invalid values; `409` duplicate category |
| PUT | `/api/categories/{id}` | Updates an event category owned by the organiser. | Organiser | Editable category fields | `200` updated category; `403` not owner; `404` not found |
| DELETE | `/api/categories/{id}` | Removes an event category when it has no enrolments. | Organiser | None | `204`; `409` if enrolments exist |
| GET | `/api/events/{id}/enrolments` | Lists all enrolments for an organiser's event. | Organiser | None; optional status/category filters | `200` enrolment list; `403` not owner |
| POST | `/api/events/{id}/enrolments` | Enrols the logged-in participant in one category for an event. | Participant | `categoryId` | `201` enrolment with race number; `400` invalid category; `409` already enrolled/full |
| GET | `/api/enrolments/me` | Lists the logged-in participant's own enrolments. | Participant | None | `200` enrolment list |
| GET | `/api/enrolments/{id}` | Returns one enrolment with event, category and result information. | Participant / Organiser | None | `200`; `403` if caller has no access; `404` not found |
| DELETE | `/api/enrolments/{id}` | Cancels the logged-in participant's own enrolment before the event closes. | Participant | None | `204`; `403` wrong owner; `409` cancellation not allowed |
| GET | `/api/events/{id}/results` | Lists participant results for an organiser-owned event. | Organiser | None | `200` results list; `403` not owner |
| POST | `/api/events/{id}/results` | Captures a result for an enrolment in an organiser-owned event. | Organiser | `enrollmentId, finishTime, position, resultStatus` | `201` result; `400` invalid result; `404` enrolment not found |
| PUT | `/api/results/{id}` | Corrects a result belonging to an organiser-owned event. | Organiser | `finishTime, position, resultStatus` | `200` updated result; `403` not owner |
| DELETE | `/api/results/{id}` | Removes an incorrectly captured result. | Organiser | None | `204`; `403` not owner |
| GET | `/api/results/me` | Returns the logged-in participant's personal result history. | Participant | None; optional event/date filters | `200` personal results |
| GET | `/api/participants/me/results` | Returns the logged-in participant's performance history and summary statistics. | Participant | None | `200` result history with totals/positions |
| GET | `/api/organiser/events` | Returns all events created by the logged-in organiser. | Organiser | None | `200` event list |
| GET | `/api/organiser/events/{id}/summary` | Returns event dashboard data: categories, enrolment counts and result counts. | Organiser | None | `200` summary; `403` not owner |
| GET | `/api/categories/{id}` | Returns details of a single category. | Public | None | `200` category; `404` not found |

## Standard response examples

### Successful participant registration

```json
{
  "userId": 7,
  "email": "participant@example.com",
  "role": "Participant",
  "message": "Account created successfully."
}
```

### Successful enrolment

```json
{
  "enrollmentId": 12,
  "eventId": 1,
  "categoryId": 2,
  "participantId": 3,
  "raceNumber": 1012,
  "status": "Confirmed"
}
```

### Validation/error response

```json
{
  "status": 400,
  "message": "The selected category does not belong to the specified event.",
  "errors": [
    "categoryId"
  ]
}
```

## API design decisions

1. The API uses resource-oriented routes and HTTP verbs rather than action names.
2. Authentication is separated from profile management so login can issue a token while `/api/profile` retrieves account data.
3. Organiser ownership is checked at the API/service layer for every event, category, enrolment-management and result-management operation.
4. Participant operations use the authenticated user identity from the JWT rather than accepting an arbitrary `participantId`, preventing one participant from accessing another participant's private data.
5. Event/category integrity is enforced by the database and validated again by the API.
6. Result records are linked to enrolments, so a result cannot exist without a valid participant registration.
7. The endpoint design maps directly to the Part 1 ERD and SQL schema to minimise rework in Part 2.
